# 플레이테스트 계획서

## 1. 목적

이 플레이테스트는 그래픽 품질이 아니라 다음 핵심 가설을 검증한다.

> 서로 연결된 두 플레이어가 각자 한쪽 팔만 사용해 싸우는 과정이 재미와 협동을 만든다.

---

# 2. 핵심 가설

## H1 연결된 이동은 협동 대화를 만든다

성공 신호:

- 플레이어가 이동 방향을 말로 조율한다.
- 같은 방향 이동을 의도적으로 시도한다.
- 연결 상태를 전략 요소로 인식한다.

실패 신호:

- 팀원의 입력을 무작위 방해로만 느낀다.
- 한 명이 사실상 이동을 포기한다.
- 연결을 없애 달라는 반응이 반복된다.

## H2 한쪽 팔 제한은 역할 분담을 만든다

성공 신호:

- 공격 순서를 맞춘다.
- 한 명이 방어하고 다른 한 명이 공격한다.
- 자신의 위치와 공격 방향을 고려한다.

실패 신호:

- 공격 버튼을 무작위로 연타한다.
- 왼팔·오른팔 차이를 느끼지 못한다.
- 한 명이 공격에 참여하지 못한다고 느낀다.

## H3 손잡기는 선택 가능한 전술이다

성공 신호:

- 포위, 탈출, 거리 확보를 위해 사용한다.
- 쿨다운을 고려해 사용 시점을 정한다.

실패 신호:

- 존재를 잊는다.
- 항상 켜는 것이 정답이다.
- 사용하면 조작이 지나치게 불안정하다.

## H4 한 명 다운 후 전투는 긴장감을 만든다

성공 신호:

- 남은 플레이어가 계속 승리를 시도한다.
- 관전자가 응원하거나 웃는다.
- 역전 가능성을 느낀다.

실패 신호:

- 다운 순간 사실상 경기가 끝났다고 느낀다.
- 드래그가 진행을 막는다.
- 남은 플레이어가 아무것도 할 수 없다.

---

# 3. 테스트 단계

## 테스트 A — 링크 이동 단독 테스트

구성:

- 아군 캐릭터 2명
- 적 없음
- 목표 지점 3개
- 팔짱과 손잡기 제공

과제:

1. 함께 직선 이동
2. 90도 방향 전환
3. 장애물 우회
4. 손잡기로 두 목표를 동시에 밟기

관찰:

- 최초 설명 후 이동 이해 시간
- 반대 방향 입력 횟수
- 구두 조율 여부
- 벽 끼임
- 손잡기 사용 이유

통과 기준:

- 2분 안에 모든 목표 완료
- 최소 1회 이상 자발적 의사소통 발생
- 치명적 끼임 없음

## 테스트 B — 전투 단독 테스트

구성:

- 움직이지 않는 연습용 적 1명
- 체력 무한
- 왼팔·오른팔 공격

과제:

1. 왼팔 공격 적중
2. 오른팔 공격 적중
3. 번갈아 4회 적중
4. 한 명 방어, 한 명 공격

관찰:

- 공격 방향 이해
- 히트박스와 시각적 동작 일치
- 공격 피드백 인지
- 공격 쿨다운 체감

통과 기준:

- 설명 후 1분 안에 역할 이해
- 번갈아 공격을 2회 이상 성공

## 테스트 C — AI 한 경기

구성:

- 플레이어 2명 vs AI 2명
- 기본 180초

관찰:

- 경기 중 대화 내용
- 이동 실패 원인
- 공격 성공 패턴
- 손잡기 사용 횟수
- 한 명 다운 이후 행동
- 재경기 의사

통과 기준:

- 경기를 처음부터 끝까지 완료
- 두 플레이어 모두 핵심 규칙을 설명 가능
- 한 명 이상 재경기 의사 표현

# 4. 참여자 구성

초기 테스트:

- 개발팀 내부 2~4명
- 게임 규칙을 알고 있는 참여자

중간 테스트:

- 게임을 자주 하는 사람 2명
- 협동 게임 경험이 적은 사람 2명
- 게임 규칙을 사전에 모르는 사람

최종 테스트:

- 2인 3팀 이상
- 팀별 최소 2경기

# 7. 인터뷰 질문

## 첫인상

- 처음 화면을 보고 무엇을 해야 한다고 생각했는가?
- 두 캐릭터가 연결되어 있다는 것을 언제 이해했는가?
- 자신이 어느 팔을 담당하는지 바로 알았는가?

## 이동

- 팀원과 같은 방향으로 움직이는 것이 쉬웠는가?
- 조작이 안 된다고 느낀 순간은 언제였는가?
- 그 원인을 화면에서 이해할 수 있었는가?
- 연결 거리는 너무 짧았는가, 길었는가?

## 전투

- 공격이 맞았다는 느낌이 분명했는가?
- 자신의 공격 범위를 예상할 수 있었는가?
- 두 사람이 번갈아 공격할 필요를 느꼈는가?
- 방어가 의미 있다고 느꼈는가?

## 손잡기

- 손잡기를 언제 사용해야 한다고 생각했는가?
- 사용 전후 차이가 충분했는가?
- 지속 시간과 쿨다운은 적절했는가?

## 다운

- 팀원이 쓰러진 뒤에도 이길 수 있다고 느꼈는가?
- 팀원을 끄는 동작은 재미있었는가, 답답했는가?
- 다운된 플레이어도 계속 참여하고 있다고 느꼈는가?

## 종합

- 가장 기억에 남는 장면은 무엇인가?
- 삭제해야 할 기능이 있다면 무엇인가?
- 반드시 개선해야 할 한 가지는 무엇인가?
- 다시 플레이하고 싶은가?
- 친구에게 이 게임을 어떻게 설명하겠는가?

# 9. 밸런스 변경 규칙

한 번의 테스트 반응만으로 핵심 규칙을 삭제하지 않는다.

수정 순서:

1. 시각적 피드백 개선
2. 수치 조정
3. 입력 방식 조정
4. 상태 규칙 조정
5. 핵심 기능 삭제 또는 교체

예시:

- 연결이 답답함 → 최대 거리를 즉시 늘리기 전에 장력 시각화와 같은 방향 보상을 먼저 조정
- 공격이 어렵다 → 히트박스 크기와 준비 시간을 먼저 조정
- 다운 이후 불가능 → 드래그 속도, 충돌체 크기, 남은 공격력을 조정

# 10. 테스트 종료 기준

다음 조건을 만족하면 온라인 MVP 개발 단계로 이동한다.

- 연결 이동의 의도를 대부분의 참여자가 이해한다.
- 두 명이 협동할수록 실제 성과가 좋아진다.
- 한쪽 팔 역할 분담이 인식된다.
- 한 명 다운 이후에도 플레이가 지속된다.
- 반복적으로 발생하는 진행 불가 버그가 없다.
- 핵심 재미가 없다는 반응보다 개선하면 재미있겠다는 반응이 우세하다.
