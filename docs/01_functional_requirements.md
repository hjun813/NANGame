# 기능 요구사항 명세서

## 1. 문서 정보

- 프로젝트명: Linked Fighters
- 버전: v0.1
- 대상: PC 웹 브라우저
- 게임 구성: 온라인 플레이어 2명 vs 적 AI 2명
- 목적: MVP 구현 범위와 완료 기준 정의

---

## 2. 요구사항 분류

| 등급 | 의미 |
|---|---|
| MUST | MVP에 반드시 포함 |
| SHOULD | 시간 내 가능하면 포함 |
| COULD | 여유가 있을 때 포함 |
| WON'T | 이번 MVP에서는 제외 |

# 3. 게임 접속 및 룸

## FR-ROOM-001 방 생성

- 우선순위: MUST
- 설명: 사용자는 새로운 게임 방을 생성할 수 있어야 한다.
- 입력: 방 생성 요청
- 처리:
  1. 서버가 고유한 방을 생성한다.
  2. 참가 가능한 방 코드를 발급한다.
  3. 생성자를 첫 번째 플레이어 슬롯에 배정한다.
- 출력: 방 코드, 현재 참가 인원, 플레이어 슬롯
- 예외:
  - 서버 생성 실패 시 오류 메시지를 표시한다.
  - 중복 방 코드를 발급하지 않는다.
- 완료 조건:
  - 서로 다른 두 방이 동일한 코드를 사용하지 않는다.
  - 생성자가 자동으로 방에 입장한다.

## FR-ROOM-002 방 코드 참가

- 우선순위: MUST
- 설명: 사용자는 유효한 방 코드를 입력하여 기존 방에 참가할 수 있어야 한다.
- 예외:
  - 존재하지 않는 방
  - 정원이 찬 방
  - 이미 시작된 방
  - 만료된 방
- 완료 조건:
  - 정상 코드 입력 시 두 번째 플레이어로 참가한다.
  - 실패 사유가 사용자에게 명확히 표시된다.

## FR-ROOM-003 플레이어 슬롯 배정

- 우선순위: MUST
- 설명: 서버는 참가 순서 또는 명시적 선택에 따라 왼쪽·오른쪽 파이터 슬롯을 배정한다.
- 규칙:
  - 한 슬롯에는 한 플레이어만 존재한다.
  - 경기 시작 후 슬롯은 변경하지 않는다.
- 완료 조건:
  - 두 클라이언트에서 동일한 슬롯 정보를 본다.

## FR-ROOM-004 준비 상태

- 우선순위: MUST
- 설명: 각 플레이어는 준비 상태를 변경할 수 있어야 한다.
- 규칙:
  - 두 플레이어가 모두 준비해야 경기 시작이 가능하다.
  - 한 명이라도 준비를 해제하면 시작하지 않는다.

## FR-ROOM-005 연결 종료 처리

- 우선순위: MUST
- 설명: 플레이어가 방이나 경기에서 이탈했을 때 서버가 상태를 정리해야 한다.
- MVP 규칙:
  - 경기 전 이탈: 남은 플레이어에게 이탈 사실을 표시한다.
  - 경기 중 이탈: 경기를 종료하고 연결 종료 결과를 표시한다.
- 재접속 복구: WON'T

# 4. 경기 흐름

## FR-GAME-001 경기 시작

- 우선순위: MUST
- 시작 조건:
  - 방에 두 플레이어가 존재한다.
  - 두 플레이어가 모두 준비 상태다.
- 처리:
  1. 서버가 경기 상태를 `COUNTDOWN`으로 변경한다.
  2. 플레이어와 AI를 초기 위치에 생성한다.
  3. 3초 카운트다운 후 `PLAYING`으로 전환한다.
- 완료 조건:
  - 두 클라이언트의 경기 시작 시점 차이가 허용 범위 내에 있다.

## FR-GAME-002 경기 타이머

- 우선순위: MUST
- 기본값: 180초
- 권한: 서버
- 규칙:
  - `PLAYING` 상태에서만 감소한다.
  - 0초가 되면 시간 종료 판정을 수행한다.

## FR-GAME-003 승리 및 패배 판정

- 우선순위: MUST
- 규칙:
  - 한 팀의 두 파이터가 모두 `DOWN`이면 해당 팀이 패배한다.
  - 상대 팀이 먼저 패배 조건을 만족하면 승리한다.
  - 같은 서버 틱에서 양 팀이 모두 패배하면 무승부다.
- 완료 조건:
  - 두 클라이언트가 동일한 경기 결과를 표시한다.

## FR-GAME-004 시간 종료 판정

- 우선순위: MUST
- 판정 순서:
  1. 생존 파이터 수
  2. 팀 전체 남은 체력 합
  3. 모두 같으면 무승부

## FR-GAME-005 재경기

- 우선순위: SHOULD
- 설명: 경기 종료 후 두 플레이어가 재경기를 선택할 수 있다.
- MVP 단순 규칙:
  - 두 플레이어가 모두 재경기를 선택하면 같은 방에서 초기화한다.

# 5. 캐릭터 이동

## FR-MOVE-001 개별 이동 입력

- 우선순위: MUST
- 입력: W, A, S, D
- 설명: 각 플레이어는 자신의 캐릭터만 이동시킨다.
- 규칙:
  - 캐릭터는 경기장 경계를 벗어날 수 없다.
  - 다른 캐릭터와 완전히 겹치지 않는다.
  - 카메라 방향과 이동 기준은 명확하게 고정한다.

## FR-MOVE-002 같은 방향 협동 이동

- 우선순위: MUST
- 설명: 두 플레이어의 이동 방향이 유사하면 팀이 안정적으로 이동해야 한다.
- 완료 조건:
  - 반대 방향 입력보다 평균 이동 속도가 높다.
  - 지속적인 떨림이나 위치 교환이 발생하지 않는다.

## FR-MOVE-003 반대 방향 이동 보정

- 우선순위: MUST
- 설명: 두 플레이어가 서로 반대 방향으로 이동할 때 연결 거리를 초과하지 않도록 이동량을 보정한다.
- 규칙:
  - 어느 한쪽만 항상 손해 보지 않도록 양쪽 이동량을 조정한다.
  - 갑작스러운 순간이동을 사용하지 않는다.

## FR-MOVE-004 벽 및 장애물 충돌

- 우선순위: MUST
- 설명: 캐릭터는 경기장 벽을 통과할 수 없다.
- 완료 조건:
  - 링크된 두 캐릭터가 벽 양쪽에 끼어 무한 진동하지 않는다.

# 6. 팀 링크

## FR-LINK-001 기본 팔짱 상태

- 우선순위: MUST
- 초기 상태: `ARM_LOCK`
- 기본 최대 거리: 1.8m
- 설명: 경기 시작 시 두 아군 파이터는 가까운 거리로 연결된다.
- 완료 조건:
  - 최대 거리 초과 시 이동량이 보정된다.
  - 연결 상태가 화면에서 식별된다.

## FR-LINK-002 손잡기 상태

- 우선순위: MUST
- 상태: `HAND_HOLD`
- 기본 최대 거리: 4m
- 지속 시간: 5초
- 재사용 대기시간: 15초
- 활성화: 팀원 중 한 명의 Space 입력
- 완료 조건:
  - 활성화 중 허용 거리가 증가한다.
  - 시간이 끝나면 자동으로 팔짱 상태로 복귀한다.
  - 쿨다운 중 재사용할 수 없다.

## FR-LINK-003 링크 시각화

- 우선순위: MUST
- 설명: 두 캐릭터 사이의 연결 상태와 장력 정도를 시각적으로 표현한다.
- 최소 표현:
  - 연결선
  - 상태별 길이 차이
  - 최대 거리 접근 경고

## FR-LINK-004 다운 드래그 상태

- 우선순위: MUST
- 상태: `DOWN_DRAG`
- 조건: 한 명만 체력 0
- 규칙:
  - 생존 파이터가 다운 파이터를 끌고 이동한다.
  - 연결은 끊어지지 않는다.
  - 생존 파이터 이동 속도는 감소한다.

# 7. 전투

## FR-COMBAT-001 왼팔 공격

- 우선순위: MUST
- 대상: 왼쪽 파이터
- 규칙:
  - 왼팔 공격만 사용할 수 있다.
  - 한 공격은 같은 대상에게 한 번만 적중한다.

## FR-COMBAT-002 오른팔 공격

- 우선순위: MUST
- 대상: 오른쪽 파이터
- 규칙:
  - 오른팔 공격만 사용할 수 있다.
  - 한 공격은 같은 대상에게 한 번만 적중한다.

## FR-COMBAT-003 공격 상태 처리

- 우선순위: MUST
- 상태 순서:
  - 준비
  - 판정 활성
  - 판정 종료
  - 후딜레이
  - 입력 가능
- 기본 공격 쿨다운: 0.7초

## FR-COMBAT-004 히트박스 판정

- 우선순위: MUST
- 설명: 공격 판정은 캐릭터 메시가 아니라 별도 히트박스를 사용한다.
- 규칙:
  - 아군 공격은 데미지를 주지 않는다.
  - 다운된 캐릭터의 공격 판정은 즉시 제거한다.

## FR-COMBAT-005 데미지 및 넉백

- 우선순위: MUST
- 기본 데미지: 12
- 처리:
  - 서버가 적중 여부를 판정한다.
  - 체력을 감소시킨다.
  - 공격 방향에 따라 넉백을 적용한다.
  - 짧은 피격 경직을 적용한다.

## FR-COMBAT-006 방어

- 우선순위: SHOULD
- 입력: K 또는 마우스 오른쪽 버튼
- 규칙:
  - 전방 공격 데미지와 넉백을 감소시킨다.
  - 방어 중 이동 속도가 감소한다.
  - 후방 공격에는 효과가 없거나 감소한다.

# 8. 체력 및 다운

## FR-HP-001 개별 체력

- 우선순위: MUST
- 기본 최대 체력: 100
- 규칙:
  - 각 파이터는 독립 체력을 가진다.
  - 체력은 0 미만으로 내려가지 않는다.

## FR-HP-002 다운 판정

- 우선순위: MUST
- 조건: 체력 0
- 처리:
  - 상태를 `DOWN`으로 변경한다.
  - 이동, 공격, 방어 입력을 차단한다.
  - 현재 공격 판정을 제거한다.

## FR-HP-003 한 명 다운 후 전투 지속

- 우선순위: MUST
- 규칙:
  - 한 명이 다운되어도 팀은 패배하지 않는다.
  - 생존 파이터는 기존 담당 팔만 사용한다.
  - 이동 속도와 회전 성능이 감소한다.

## FR-HP-004 팀 패배

- 우선순위: MUST
- 조건: 같은 팀의 두 파이터가 모두 `DOWN`

# 12. 비기능 요구사항

## NFR-001 성능

- 목표 렌더링 성능: 일반 PC 브라우저에서 평균 60 FPS 지향
- 최소 허용 기준: 전투 중 지속적으로 30 FPS 미만이 되지 않아야 한다.
- 네트워크 메시지와 렌더링 루프를 분리한다.

## NFR-002 네트워크 일관성

- 공격, 체력, 다운, 승패는 서버 상태를 기준으로 한다.
- 두 클라이언트에서 경기 결과가 달라져서는 안 된다.

## NFR-003 복구 가능성

- 경기 중 연결이 끊겨도 서버가 방과 세션을 정리할 수 있어야 한다.
- 무한 대기 상태를 만들지 않는다.

## NFR-004 브라우저 지원

- 1차 지원: 최신 Chrome
- 2차 확인: Edge
- 모바일 브라우저: 제외

## NFR-005 유지보수성

- 공용 상태 타입과 상수는 `shared` 모듈에서 관리한다.
- 게임 규칙 수치를 코드 여러 곳에 중복 작성하지 않는다.
- 상태 전환은 명시적인 함수 또는 상태 머신으로 처리한다.

## NFR-006 관측 가능성

개발 빌드에서 다음 정보를 확인할 수 있어야 한다.

- FPS
- 서버 틱
- 핑
- 캐릭터 상태
- 링크 상태
- 캐릭터 간 거리
- 공격 히트박스
- 체력
- 방 코드
