- [x] 캡슐 콜라이더 생성

성공 기준:

- 벽 통과 없음

## TV-PHY-002 규칙 기반 링크 보정

검증 방식:

1. 두 캐릭터 예상 이동 위치 계산
2. 최대 거리 초과 여부 계산
3. 이동 벡터 수정
4. 수정된 위치를 물리 객체에 반영

- [ ] 1.8m 제한
- [ ] 4m 제한
- [ ] 같은 방향 입력
- [ ] 반대 방향 입력
- [ ] 한 명만 입력
- [ ] 벽 근처 입력

성공 기준:

- Joint 없이 거리 제한 가능
- 최대 거리에서 폭발적인 반발 없음
- 30초 연속 반대 방향 입력에도 시뮬레이션 안정

## TV-PHY-003 다운 드래그

- [ ] 다운 캐릭터의 충돌체 크기 변경 가능
- [ ] 생존 캐릭터가 이동할 때 따라오기
- [ ] 벽 모서리 보정
- [ ] 최대 후행 거리 제한

성공 기준:

- 30초 드래그 테스트 중 진행 불가 상태가 발생하지 않음

# 10. 기술 의사결정 게이트

다음 질문에 답하기 전까지 본 개발로 넘어가지 않는다.

## Gate A — 링크 구현 방식

- 규칙 기반 이동 보정만으로 안정적인가?
- Rapier Joint가 실제로 필요한가?
- 서버와 클라이언트에서 동일한 링크 계산을 재사용할 수 있는가?

## Gate B — 시뮬레이션 위치

- 이동과 충돌을 모두 서버에서 계산할 것인가?
- 클라이언트 예측을 MVP에 포함할 것인가?
- AI는 서버에서만 실행 가능한가?

## Gate C — 성능

- 4개 캐릭터와 충돌에서 목표 FPS를 유지하는가?
- 서버 30 tick/s가 안정적인가?
- 스냅샷 20회/s가 충분한가?

## Gate D — 배포

- 외부 환경에서 WebSocket이 정상 연결되는가?
- 무료 또는 해커톤 배포 환경에서 슬립·타임아웃 문제가 없는가?
