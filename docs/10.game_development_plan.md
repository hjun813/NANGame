# MVP 개발 계획서

## 1. 문서 목적

이 문서는 게임의 핵심 재미를 빠르게 검증하고, 온라인 플레이가 가능한 MVP를 완성하기 위한 개발 순서와 완료 조건을 정의한다.

개발은 다음 원칙을 따른다.

> 그래픽과 온라인 기능보다 연결된 이동과 전투의 재미를 먼저 검증한다.

---

## 2. 개발 목표

### 최종 MVP 목표

두 명의 사용자가 각자의 PC에서 같은 방에 접속해 서로 연결된 파이터를 한 명씩 조작하고, 적 AI 두 명과 한 경기를 정상적으로 완료할 수 있어야 한다.

### MVP 완료 상태

* 방 생성과 참가가 가능하다.
* 두 플레이어의 이동이 실시간으로 동기화된다.
* 두 아군 캐릭터가 연결된 상태로 움직인다.
* 각 플레이어가 자신의 담당 팔로 공격한다.
* 적 AI가 이동하고 공격한다.
* 체력, 다운, 승리 및 패배가 정상적으로 작동한다.
* 한 명이 다운되면 팀원이 끌고 싸울 수 있다.
* 경기 종료 후 재경기가 가능하다.
* 일반적인 네트워크 환경에서 한 경기를 완료할 수 있다.

## 3. 권장 기술 구성

### 클라이언트

* TypeScript
* React
* Three.js
* Rapier.js
* Vite

### 서버

* Node.js
* TypeScript
* Colyseus

### 통신

* WebSocket
* 서버 권한형 게임 상태 관리

### 배포

* 클라이언트: 정적 웹 호스팅
* 게임 서버: Node.js 실행이 가능한 서버
* 통신: HTTPS 및 WSS

### 기술 선택 이유

#### Three.js

웹 브라우저에서 3D 경기장, 캐릭터, 카메라와 조명을 구현하기 적합하다.

#### Rapier.js

충돌 판정과 기본적인 물리 처리를 제공하면서 웹 환경에서 비교적 안정적인 성능을 기대할 수 있다.

#### Colyseus

방 생성, 참가, 상태 동기화와 플레이어 세션 관리 기능을 제공하므로 해커톤 환경에서 직접 룸 서버를 처음부터 구현하는 부담을 줄일 수 있다.

# 단계 1. 로컬 그레이박스 구현

## 목표

그래픽 없이 캐릭터와 경기장의 기본 구조를 만든다.

## 구현 범위

* 기본 3D 경기장
* 바닥과 벽
* 캡슐 형태 캐릭터 4개
* 아군 캐릭터 2개
* 적 캐릭터 자리 표시용 오브젝트 2개
* 키보드 이동
* 캐릭터 충돌
* 기본 쿼터뷰 카메라
* 디버그 정보 표시

## 초기 조작 환경

첫 번째 프로토타입에서는 한 컴퓨터에서 두 캐릭터를 조작해도 된다.

예시:

* 플레이어 A: WASD
* 플레이어 B: 방향키

온라인 기능을 구현하기 전에 로컬에서 연결 이동을 검증한다.

## 완료 기준

* 두 캐릭터를 각각 움직일 수 있다.
* 캐릭터가 벽을 통과하지 않는다.
* 캐릭터가 지나치게 겹치지 않는다.
* 카메라에서 두 캐릭터를 확인할 수 있다.
* 새로고침 후 동일한 테스트를 반복할 수 있다.

---

# 단계 2. 팀 링크 및 협동 이동 구현

## 목표

게임의 핵심인 연결된 이동을 구현하고 재미를 검증한다.

## 구현 범위

* 두 아군 캐릭터 사이 거리 계산
* 팔짱 상태 최대 거리
* 연결 거리 초과 방지
* 같은 방향 이동 보정
* 반대 방향 이동 보정
* 한 명만 움직일 때 끌림 처리
* 링크 시각화
* 연결 장력 디버그 표시
* 손잡기 상태 전환
* 손잡기 지속 시간과 쿨다운

## 기술 원칙

* 물리 Joint만으로 캐릭터를 연결하지 않는다.
* 입력과 예상 위치를 먼저 계산한다.
* 연결 규칙에 따라 이동량을 보정한다.
* 시각적인 흔들림과 장력만 제한적으로 물리 효과로 표현한다.

## 검증 질문

* 한 명이 이동할 때 다른 한 명의 영향이 자연스러운가?
* 두 명이 같은 방향으로 움직이면 보상이 느껴지는가?
* 반대 방향 이동이 답답하지만 이해 가능한가?
* 최대 연결 거리가 화면에서 명확하게 전달되는가?
* 손잡기 상태가 실제로 새로운 이동 전략을 만드는가?

## 완료 기준

* 캐릭터가 링크 최대 거리를 벗어나지 않는다.
* 이동 중 심한 떨림이 발생하지 않는다.
* 벽 근처에서도 캐릭터가 폭발적으로 튀지 않는다.
* 팔짱과 손잡기의 차이를 조작으로 느낄 수 있다.
* 두 사람이 함께 이동할 이유가 존재한다.

# 단계 3. 기본 전투 구현

## 목표

역할이 분리된 한쪽 팔 공격과 피격 감각을 구현한다.

## 구현 범위

* 왼팔 공격
* 오른팔 공격
* 공격 상태
* 공격 히트박스
* 공격 쿨다운
* 적중 판정
* 데미지
* 피격 경직
* 넉백
* 기본 방어
* 공격 및 피격 디버그 표시

## 구현 순서

1. 공격 입력 처리
2. 공격 상태 전환
3. 히트박스 활성화
4. 충돌 대상 확인
5. 중복 적중 방지
6. 데미지 적용
7. 넉백 적용
8. 공격 종료
9. 다시 입력 가능한 상태로 복귀

## 완료 기준

* 왼쪽 파이터는 왼팔 공격만 사용한다.
* 오른쪽 파이터는 오른팔 공격만 사용한다.
* 한 번의 공격이 한 번만 적중한다.
* 공격 거리와 실제 판정이 크게 어긋나지 않는다.
* 피격 시 즉시 알아볼 수 있는 반응이 발생한다.
* 공격을 무한히 연속 사용할 수 없다.
* 방어 방향에 따라 데미지가 감소한다.

---

# 단계 4. 체력, 다운 및 팀원 끌기 구현

## 목표

게임의 대표적인 후반 상황인 팀원 끌기 전투를 구현한다.

## 구현 범위

* 개별 체력
* 체력 감소
* 체력 0 판정
* 다운 상태
* 다운된 플레이어 입력 차단
* 생존 파이터의 이동 속도 감소
* 다운 팀원 위치 추적
* 다운 팀원 드래그
* 두 명 다운 시 패배
* 디버그용 체력 UI

## 구현 원칙

* 다운 캐릭터의 완전한 래그돌은 사용하지 않는다.
* 안정적인 바닥 추적과 드래그를 우선한다.
* 다운 캐릭터가 벽이나 오브젝트에 걸려 생존 플레이어를 완전히 막지 않도록 한다.
* 생존 플레이어는 기존에 담당하던 팔만 사용한다.

## 완료 기준

* 한 명이 다운되어도 경기가 계속된다.
* 다운된 플레이어는 공격하거나 이동할 수 없다.
* 생존 플레이어가 다운 팀원을 끌 수 있다.
* 드래그 중 심한 떨림이나 순간이동이 발생하지 않는다.
* 두 명이 모두 다운되면 즉시 패배한다.
* 한 명만 남은 상태에서도 공격이 가능하다.

# 단계 5. 적 AI와 경기 흐름 구현

## 목표

플레이어 두 명이 처음부터 끝까지 한 경기를 진행할 수 있도록 한다.

## 구현 범위

* AI 상태 머신
* 플레이어 접근
* 공격
* 방어
* 후퇴
* 위치 재조정
* AI 팀 링크
* AI 다운 및 드래그
* 시작 카운트다운
* 경기 타이머
* 승리 및 패배
* 재시작

## AI 구현 순서

1. 가장 가까운 플레이어 탐색
2. 접근
3. 공격 범위 확인
4. 공격 또는 방어
5. 공격 후 후퇴
6. 벽과 팀원 위치 확인
7. 필요 시 중앙으로 이동
8. 한 AI가 다운되면 드래그 상태 전환

## 완료 기준

* AI가 플레이어에게 접근한다.
* AI가 공격과 후퇴를 반복한다.
* AI 두 명이 계속 겹치지 않는다.
* AI가 벽에 영구적으로 멈추지 않는다.
* AI도 연결 거리 규칙을 지킨다.
* 플레이어가 적 두 명을 쓰러뜨리면 승리한다.
* 플레이어 두 명이 쓰러지면 패배한다.
* 결과 화면에서 재경기를 시작할 수 있다.

플레이어가 경기 정보와 연결 상태를 명확하게 파악할 수 있도록 한다.

* 마우스 드래그 회전
* 휠 확대 및 축소
* 카메라 상하 각도 제한
* R 키 초기화
* 벽 충돌 보정
* 아군 체력 UI
* 적 체력 UI
* 손잡기 지속 시간
* 손잡기 쿨다운
* 경기 시간
* 승리 및 패배 화면

* 각 플레이어가 카메라를 독립적으로 조작할 수 있다.

# 단계 7. 온라인 멀티플레이 적용

## 목표

각자 다른 컴퓨터에서 두 명이 협동 플레이할 수 있도록 한다.

## 구현 범위

* 게임 서버 생성
* 방 생성
* 방 코드 발급
* 방 참가
* 플레이어 슬롯 배정
* 준비 상태
* 게임 시작
* 이동 입력 전송
* 서버 위치 계산
* 위치 보간
* 공격 입력 전송
* 공격 및 데미지 서버 판정
* 링크 상태 동기화
* AI 서버 실행
* 경기 결과 동기화
* 연결 종료 처리

## 네트워크 구현 순서

### 1. 로비

* 방 생성
* 방 코드 참가
* 플레이어 목록
* 준비 상태

### 2. 이동

* 입력값 서버 전송
* 서버에서 이동 계산
* 서버 상태 브로드캐스트
* 클라이언트 위치 보간

### 3. 링크

* 서버에서 두 플레이어 거리 계산
* 이동 제한 서버 적용
* 링크 상태 공유

### 4. 전투

* 공격 요청 전송
* 서버가 공격 가능 여부 확인
* 서버가 적중 판정
* 서버가 체력과 다운 상태 갱신

### 5. AI

* 서버에서 AI 상태 머신 실행
* AI 위치와 행동 전송

### 6. 경기 상태

* 카운트다운
* 타이머
* 승리 및 패배
* 재경기

* 서로 다른 두 브라우저에서 같은 방에 참가할 수 있다.
* 각 플레이어가 자신의 캐릭터만 조작한다.
* 두 화면에서 캐릭터 위치가 크게 어긋나지 않는다.
* 공격 결과와 체력이 두 화면에서 동일하다.
* AI 행동이 두 화면에서 동일하게 보인다.
* 한 경기를 처음부터 끝까지 진행할 수 있다.
* 연결 종료 시 게임이 멈추거나 무한 대기하지 않는다.

# 단계 8. 연출 및 사용성 개선

## 목표

기능적으로 작동하는 게임을 실제 플레이 가능한 수준으로 개선한다.

## 구현 우선순위

1. 타격음
2. 피격 이펙트
3. 공격 궤적
4. 짧은 화면 흔들림
5. 히트 스톱
6. 체력 감소 애니메이션
7. 손잡기 활성화 효과
8. 링크 장력 표현
9. 다운 연출
10. 배경 음악

## 완료 기준

* 공격 적중 여부를 즉시 알 수 있다.
* 공격 실패와 성공이 명확히 구분된다.
* 손잡기 활성화와 종료를 쉽게 확인할 수 있다.
* 다운 상황이 명확하게 전달된다.
* 연출 때문에 조작이나 판정이 가려지지 않는다.

* 한 명이 다운된 이후에도 승리 가능성을 느꼈는가?
* 가장 재미있었던 장면은 무엇인가?
* 가장 답답했던 장면은 무엇인가?
* 다시 플레이하고 싶은가?

### 완료 정의

기능은 다음 조건을 모두 만족해야 완료로 처리한다.

* 정상 상황에서 작동한다.
* 주요 예외 상황을 처리한다.
* 재현 가능한 테스트 방법이 있다.
* 다른 기능을 심각하게 손상시키지 않는다.
* 콘솔에 반복적인 오류가 발생하지 않는다.
* 문서와 실제 동작이 일치한다.

## 8. 주요 개발 위험

### 연결 물리 불안정

#### 문제

캐릭터가 떨리거나 순간적으로 튈 수 있다.

#### 대응

* 물리 Joint 의존도를 낮춘다.
* 이동량을 규칙 기반으로 보정한다.
* 최대 이동량을 제한한다.
* 서버와 클라이언트에서 같은 계산 규칙을 사용한다.

### 온라인 동기화 난이도

#### 문제

두 캐릭터가 서로 연결되어 있어 작은 위치 오차가 크게 보일 수 있다.

#### 대응

* 서버 권한형 구조를 사용한다.
* 위치 자체보다 입력을 서버로 전달한다.
* 클라이언트에서 보간을 적용한다.
* 초기에는 낮은 동시 접속 인원만 지원한다.

### 다운 캐릭터 걸림

#### 문제

쓰러진 캐릭터가 벽이나 적에게 걸려 생존 플레이어가 이동하지 못할 수 있다.

#### 대응

* 완전한 래그돌을 사용하지 않는다.
* 다운 캐릭터 충돌 범위를 축소한다.
* 일정 거리 이상 뒤처지면 위치를 보정한다.
* 이동 불가 상태가 지속되면 안전 위치로 이동한다.

### 조작의 답답함

#### 문제

연결 제약이 협동보다 방해로 느껴질 수 있다.

#### 대응

* 같은 방향 입력에 명확한 이동 보상을 제공한다.
* 반대 방향 입력도 완전히 정지시키지 않는다.
* 연결 장력과 제한 상태를 시각적으로 표현한다.
* 손잡기 상태로 선택 가능한 해결 수단을 제공한다.

### AI 구현 시간 증가

#### 문제

AI 두 명이 서로 연결된 규칙까지 처리해야 하므로 복잡도가 높다.

#### 대응

* 복잡한 전략 AI를 구현하지 않는다.
* 접근, 공격, 후퇴 중심의 상태 머신을 사용한다.
* 초기 버전에서는 AI 두 명이 하나의 팀 목표를 공유하도록 한다.
